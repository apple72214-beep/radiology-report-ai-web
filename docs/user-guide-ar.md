# دليل استخدام منصة Radiology report AI (نسخة المتصفح)

منصة تقارير أشعة تعمل بالكامل داخل متصفحك: لا سيرفر، لا بيانات تغادر جهازك، وبعد أول تشغيل ناجح تُخزَّن النسخة على جهازك وتعمل دون إنترنت.

## 1) الفتح أول مرة
1. افتح الرابط: `https://radiology-report-ai-web.vercel.app/x` (أو أي مسار طازج يُعطى لك: `/y` أو `/z` أو `/r1/start.html`).
2. انتظر حتى تظهر الواجهة الكاملة (سطر التحميل قد يعدّ ثوانٍ على الشبكات الضعيفة — دعه يواصل).
3. بعد أول نجاح يُسجَّل «عامل الخدمة» (SW): من thereafter افتح الرابط المعتاد `.../start.html` وسيعمل حتى بدون شبكة.
4. اختياري (يُستحسن): من قائمة المتصفح ← «إضافة إلى الشاشة الرئيسية» ليصير أيقونة كتطبيق.

## 2) إدخال الدراسات
- **ملفات DICOM من جهازك**: «اختيار الملفات» ← اختر `.dcm` أو `.zip` منها ← «رفع وتحليل». تُفرز آليًا (حرج / استشارة / روتيني) وتدخل قائمة العمل.
- **منذ v43**: زر «اختيار مجلد DICOM كامل» يفتح منتقي المجلدات على جهازك (مسار مثل: المريض ← S00004 ← SER00001) فيقرأ **كل الملفات داخله دفعة واحدة** حتى لو كانت بلا امتداد (BIN)، ويتخطى غير DICOM تلقائيًا ويخبرك بعدد المتخطى. بديل مكافئ: اضغط المجلد إلى `.zip` بأي مدير ملفات واختر الـZIP وحده.
- **تجربة سريعة بلا ملفات**: «توليد ديمو» ← دراستان جاهزتان (DEMO-0001 حرج، DEMO-0002 روتيني).
- الشارة الحمراء = حرج (عدم تناظر بين ساحتي الرئتين)، الزرقاء = استشارة، الخضراء = روتيني.

## 3) العارض
- «عرض» بجانب أي دراسة تفتح العارض.
- **الشريحة**: المنزلق يقلّب شرائح الدراسة (متزامن مع كل الألواح).
- **قطع**: قائمة النوافذ (رئات/منصف/عظم…) لتغيير تباين العرض.
- **1:1** تكبير طبيعي، والسحب يحرك الصورة.
- **قياس**: وضع القياسات (مسافة بالمم عبر بيانات البكسل، زاوية، ومنطقة ROI بمتوسط HU) ثم «مسح القياسات» يفرغها.

## 4) المقارنة مع دراسة سابقة (باب v1.1)
1. افتح الدراسة الحالية في العارض.
2. اضغط «مقارنة» واختر الدراسة الأخرى من القائمة المجاورة.
3. تظهر ثلاثة ألواح: **الحالية / السابقة-الأخرى / خريطة الفرق (أحمر = ساخن)** + سطر الإحصاء: «متوسط الفرق … والنقاط الساخنة …% (عتبة 0.25 بعد التطبيع)».
4. تُحفظ النتيجة مع الدراسة وتدخل تلقائيًا مسودة التقرير.

## 5) التقرير والتوقيع والتصدير
1. «توليد مسودة التقرير (ع/EN)»: مسودة عربية وإنجليزية (انطباع، فرز آلي، سياق، مقارنة) — **قرار داعم وليس تشخيصًا**.
   نفس الضغطة تنزل تلقائيًا ملف Word إنجليزي `rrai-report-EN-<patient>.docx` بالقالب السريري (عنوان كحلي مركزي، كتلة بيانات المريض، عناوين TECHNIQUE/FINDINGS/IMPRESSION زرقاء، صندوق انطباع مظلل، بلوك Reported by يمينًا، وبصمة SHA-256 أسفله). زر مستقل «تصدير Word (قالب EN)» بجانب زر Word القديم يعيد توليده بعد التعديل.
2. راجع النص وصحّح ما يلزم يدويًا.
3. أدخل اسمك ورقم ترخيصك/النقابة (اختياري لكنه يظهر في بلوك التوقيع ويُحفظ مع الدراسة).
4. «توقيع وتصدير PDF» أو «توقيع وتصدير Word»: يُحسب SHA-256 للوثيقة ويُدرج مع التوقيع؛ افتح الملف في Xodo (PDF) أو WPS Office Lite (Word).
5. ترويسة مؤسستك: «إعدادات ترويسة المؤسسة» ← اكتب اسم المنصة بالعربي/الإنجليزي ← «حفظ الترويسة» فتظهر في كل التقارير.

## 6 حلقة الاستشارة عن بُعد (تيلراديولوجي)
- عندك حالة تريد رأي زميل: «تصدير حزمة استشارة» (نص+لقطة+بيانات) ← انسخها أو أرسل الملف.
- الزميل: «استيراد حزمة استشارة» أو «استيراد من الحافظة» أو «استيراد آخر حزمة مصدّرة» ← تدخل الحالة قائمته مع لقطة وسياق، ويردّ بمسودة تقريره الخاصة.
- التحقق مغلق: أي حزمة معدّلة تُرفض برسالة واضحة.

## 7) الخصوصية والتنظيف
- كل المعالجة داخل متصفحك؛ لا شيء يُرفع لأي سيرفر.
- «تفريغ القائمة من الجهاز» يحذف الدراسات من تخزين الجهاز نهائيًا.
- لإزالة كل أثر: إعدادات Chrome ← إعدادات الموقع ← مسح بيانات الموقع.

## 8) إذا تعثّر الفتح على شبكة محصورة
1. صفحة التشخيص: `.../d` تعرض مرحلة الإقلاع وآخر خطأ وحالة SW ومعها أزرار إنقاذ.
2. جرّب مسارًا طازجًا بالترتيب: `/x` ثم `/y` ثم `/z` ثم `/r1/start.html`.
3. بدّل الواي فاي إلى بيانات الجوال (أو العكس) وأعد الفتح.
4. لا تمسح بيانات الموقع إلا كحل أخير (يضيع التخزين المحلي).

## تذكير سريري
المنظومة **نظام دعم قرار**: كل مسودة تحمل إخلاء المسؤولية، والاعتماد النهائي مسؤولية الطبيب المختص الموقع.

## 9) ربط PACS المستشفى أو تطبيق قارئ DICOM (جسر Orthanc)
حوار DICOM الكلاسيكي (AE title / منفذ 11112 / C-GET / C-MOVE) بروتوكول TCP خام لا تتكلمه المتصفحات؛ الجسر هو **Orthanc** المضمّن في حزمة الطرف:
1. على جهاز داخل الشبكة: `docker compose -f docker/docker-compose.yml up -d` — يشغل المنصة (8080) **ومعه Orthanc** (منفذ DICOM‏ 4242 وDICOMweb على `/dicom-web/` خلف nginx المضمّن بترويسات CORS).
2. عدّل `docker/orthanc.json`: ضع في `DicomModalities.hospital_pacs` نفس قيم حوار «New server» (AE title للأرشيف، عنوانه، منفذه) وأعد التشغيل؛ اسحب الدراسات عبر REST أو اجعل الأرشيف يرسل C-MOVE إلى AET‏ `RRAI`.
3. في المنصة افتح «سحب من PACS (DICOMweb)» وأدخل `http://<edge-ip>:8080/dicom-web` — نفس الأصل بلا وكيل؛ العناوين الداخلية تُطلب مباشرة وأطراف الإنترنت العامة تمر عبر وكيل `/api/dicomweb`.
4. تطبيق القارئ على هاتفك يربط على **نفس Orthanc**: Name حر، AE title‏ `RRAI`، Host عنوان جهاز الطرف، Port‏ `4242`، Retrieve‏ C-GET — فيقرأ الاثنان نفس مخزن الحالات.
بديل بلا سيرفر: صدّر/شارك ملفات `.dcm` من تطبيق القارئ وارفعها في المنصة عبر «اختيار الملفات».
5. زر «سحب من رابط تنزيل (WeTransfer/ZIP/DICOM)» له منذ v42 حقل مستقل باسم «رابط التنزيل» داخل نفس القائمة؛ الصق فيه رابط WeTransfer أو ZIP أو `.dcm` مباشر ثم اضغط الزر. إن تركت الحقل فارغًا يفتح الزر نافذة لصق نظامية، والرابط يُستخرج حتى لو لصقته داخل جملة أو بلا `https://`. روابط WeTransfer تُفك عبر خادم المنصة؛ وإن طلبت WeTransfer تحققًا بشريًا من الخادم تظهر رسالة واضحة والبديل «اختيار الملفات» أو رابط ZIP مباشر.

## 10) التأليف بمساعدة AI (اختياري — بلا بطاقة ائتمان)
من العارض ← «تأليف التقرير التشخيصي»: اختر المزوّد ثم الصق مفتاح API (يُحفظ على جهازك فقط):
1. **Groq (الافتراضي، بلا بطاقة)**: console.groq.com ← Sign up ببريد أو Google ← تحقق من البريد ← الشريط الجانبي «API Keys» ← Create API Key ← انسخه فورًا (يظهر مرة واحدة) ← الصقه في المنصة.
2. **OpenRouter (بلا بطاقة)**: openrouter.ai/keys ← تسجيل ببريد أو GitHub ← Create Key ← الصقه؛ تُستخدم نماذج `:free` فقط.
3. **Google Gemini**: فقط إن لم يطلب حسابك فوترة/بطاقة (جدار فوترة إقليمي يظهر لبعض الحسابات) — وإن طلبها فتجاهله واستخدم Groq.
عند الضغط «توليد بمساعدة AI» يظهر حوار موافقة لكل طلب: تُرسل 3 لقطات شرائح مصغّرة (≤512px) + إحصاءات رقمية فقط — لا ملفات DICOM خام — وتعود مسودة JSON (فحص/دلالة/وصف/انطباع) تُصبّ في حقول التأليف قابلة للتحرير قبل التصدير والتوقيع. بلا مفتاح أو بلا إنترنت تبقى لوحة التأليف وبنك الصياغات والتصدير تعمل كلها محليًا.

## 11) القائمة الجانبية ونافذة الإعدادات (منذ v95–v96)
زر **☰** في الترويسة يفتح درجًا جانبيًا يعمل باللمس: الحالة (متصل/دون إنترنت + عدد الدراسات)، قائمة العمل، «الحرج فقط» مع العدّ الحي، الأرشيف، «إدارة البيانات ▾» (مجموعة أزرار مطوية)، التأليف بمساعدة AI، **⚙ الإعدادات**، تثبيت التطبيق (PWA)، والمساعدة.

نافذة **⚙ الإعدادات** عشرة أقسام مطوية:
1. **🏥 الشبكة وPACS**: رابط DICOMweb، رمز Bearer (يُحفظ محليًا)، «اختبار الاتصال»، السحب التلقائي (معطّل/5/15/30 دقيقة — الاستيراد يتم **بتأكيدك** لا صامتًا)، وحقلا AE Title والمنفذ لتوثيق إعدادات الأنظمة القديمة (الاتصال الفعلي عبر HTTP).
2. **🤖 الذكاء والتنبيهات**: تنبيه الدراسات الحرجة الجديدة (نغمة 880Hz + اهتزاز حيث يُدعم).
3. **💾 التخزين والبيانات**: تقدير المساحة المستخدمة، تفريغ صور الدراسات المؤرشفة تقاريرها، إخفاء هوية المريض في حزم الاستشارة المصدّرة، تنعيم الصور (تعطيله يسرّع الشرائح الكثيفة)، إعادة بناء مخبأ الأوفلاين، وتفريغ قاعدة الدراسات المحلية (بتأكيد — التقارير المؤرشفة تبقى).
4. **🎨 العرض واللغة**: لغة الواجهة (العربية/English) والمظهر (داكن طبي/فاتح).
5. **🖥 تفضيلات العارض**: النافذة الافتراضية عند فتح دراسة (تلقائي/رئة/منصف/عظم)، إظهار أو إخفاء اسم المريض وسطر معلومات الشريحة، لون أدوات القياس (منتقي ألوان) ووحدتها (مم/سم).
6. **📋 قائمة العمل**: الفرز الافتراضي (الحرج أولًا/الأحدث/أبجديًا) وفتح أول دراسة تلقائيًا بعد رفع مجلد.
7. **⌨ اختصارات لوحة المفاتيح**: انظر القسم 12.
8. **📤 الاستيراد والتصدير**: تنسيق التصدير الافتراضي (Word أو PDF — يُبرز الزر الأساسي تلقائيًا) وضغط gzip لحزم الاستشارة (الاستيراد يكتشف `.json.gz` ويفكّها تلقائيًا ويقبل `.json` العادية كما قبل).
9. **🔒 الخصوصية والأمان**: مدة الحذف التلقائي للمسودات/الدراسات (30–365 يومًا أو تعطيل) وللموقّع (90 يومًا–سنتان أو تعطيل).
10. **ℹ حول التطبيق**: الإصدار، حالة الاتصال الحية، الإخلاء الطبي، سياسة الخصوصية، التراخيص (تنفيذ أصلي بلا مكتبات خارجية)، وقناة الدعم.

## 12) اختصارات لوحة المفاتيح (v96–v97)
| الوظيفة | المفتاح الافتراضي |
|---|---|
| الشريحة التالية | `→` ArrowRight |
| الشريحة السابقة | `←` ArrowLeft |
| ملاءمة العرض | `f` |
| وضع القياس | `m` |
| تكبير (×1.25 حتى ×8 مع إعادة توسيط) | `+` |
| تصغير (حتى ×0.5) | `-` |
| تبديل التباين (يدوّر نوافذ العارض) | `c` |

كل الاختصارات **قابلة للتخصيص**: افتح ⚙ ← قسم ⌨ ← اضغط داخل الحقل ثم اضغط المفتاح المطلوب. تُتجاهل الضغطات أثناء الكتابة في أي حقل نصي حتى لا تتعارض مع الإدخال.

## 13. إن تعذّر التحديث (شبكة تحجب المصادر)

1. افتح **`standalone.html`** — «نسخة الملف الواحد»: الواجهة وكل الوحدات مضمّنة داخل صفحة واحدة،
   فلا تحتاج أي اتصال خارجي بعد تحميلها، ولا تتأثر بعامل خدمة قديم ولا ببروكسي الشبكة.
2. افتح **`diag.html`** لمعرفة أيّ المصادر الخارجية (GitHub، jsDelivr، githack، allorigins)
   محجوب أو يُرجع 404 عندك.
3. من داخل التطبيق: ☰ ← حول ← «فتح نسخة الملف الواحد / تشخيص».
4. الملاذ الأخير: إعدادات المتصفح ← بيانات الموقع ← مسح البيانات، ثم أعد الفتح.

### تنزيل نسخة الملف الواحد (ملف محلي)

يمكنك تنزيل `standalone.html` وفتحه من مدير الملفات في هاتفك: **تعمل دون خادم ودون اتصال**
(مُجرَّبة على Chrome للأندرويد). الاستخدام اليومي يبقى عبر التطبيق المثبّت من الموقع؛
الملف المحلي مفيد للسفر أو لجهاز بلا إنترنت. ننصح بتصدير نسخة احتياطية دوريًا لأن التخزين
المحلي للملفات قد يختلف عن تخزين النطاق.

## 15. تاريخ الدراسة

- يظهر الآن عمود **التاريخ** في قائمة العمل لكل حالة (مع الوقت إن وُجد في الملف).
- إن كان وسم التاريخ ناقصًا في ملفاتك (وهو شائع في الدراسات المُصدَّرة)، يبحث التطبيق بالترتيب:
  تاريخ الدراسة ← تاريخ السلسلة ← تاريخ الاكتساب ← تاريخ إنشاء الصورة ← تاريخ المحتوى.
- يمكنك **الفرز حسب تاريخ الفحص** (الأحدث أولًا) من إعدادات قائمة العمل.

## 16. طبقة المعلومات على الصورة (نوع الفحص والتسلسل)

- تظهر زوايا الصورة الآن: اسم المريض (اختياري)، التاريخ والنمط، و**رقم السلسلة ونوع التسلسل**
  (T1 / T2 / FLAIR / DWI / ADC / T2* / STIR / MRA-TOF …)، ورقم الشريحة و TE/TR.
- **المصدر أولًا**: الاسم يُقرأ من وسوم الملف (وصف السلسلة، اسم التسلسل، البروتوكول، نوع الصورة).
  إن كانت كلها فارغة، يُستنتج من زمني TR/TE/TI أو قيمة b في MR — ويُوسم أي اسم مستنتج بعلامة
  **`~`** لتعرف أنه استنتاج لا نصّ ملف.
- من الإعدادات ← تفضيلات العارض: تشغيل/إطفاء طبقة المعلومات، وتشغيل/إطفاء TE/TR.

## 17. حين لا تظهر الصورة (تشخيص الإطار الأسود)

- **لا شاشات سوداء صامتة بعد اليوم.** إن كان الملف لا يحمل بيانات بكسل قابلة للعرض، يرفضه
  التطبيق عند الاستيراد ويخبرك: «تحذير: N ملفًا لا تحمل بيانات بكسل قابلة للعرض ولم تُخزّن».
- إن كانت دراسة مخزّنة قديمًا بهذا العيب، يرسم العارض **لوحة سبب** مكتوبة بدل المستطيل الأسود،
  مع صندوق تحت الصورة يشرح السبب بالأرقام (عدد البايتات الموجودة/المطلوبة، عمق البتّ، صيغة
  النقل). و**MPR** لن يعرض ثلاث نوافذ سوداء — يتراجع للعرض المفرد ويذكر السبب.
- زر **نسخ التشخيص** تحت الصورة ينسخ تقريرًا جاهزًا (الدراسة، السلاسل، الأبعاد، len/need،
  البتّات، Photometric، Transfer Syntax، min/max). ألصقه في المحادثة عند طلب المساعدة.
- صفحة **فاحص ملف DICOM** على `/probe.html`: اسحب ملفًا واحدًا من ملفات دراستك، فتظهر صيغة
  النقل (مضغوطة أم لا)، الأبعاد، عمق البتّ، عدد بايتات البكسل مقابل المطلوب، المدى، ومعاينة
  مصغّرة بأقصى تباين — وكل شيء داخل المتصفح.

### 18. النافذة الذكية (v105)

- إن كانت قيمة واحدة (هواء/حشو/نطاق مسطّح) تملأ معظم الإطار، تنهار نافذة ٢–٩٨٪ فيصبح كل
  البكسلات بنفس الرمادي وتظهر الصورة **سوداء مع أن البيانات سليمة**. العارض الآن يقيس ما
  رسمه فعليًا، فإن كان موحّدًا أعاد حساب النافذة **خارج النطاق المهيمن** وأعاد الرسم.
- لن يُعاد استخدام صورة سوداء مخزّنة في ذاكرة الإطار من إصدار أقدم.
- إن تعذّر كل ذلك تظهر **لوحة السبب** بالأرقام بدل المستطيل الأسود.
- **رقم الإصدار يظهر في رأس العارض** (مثل `MR • v105`) لتعرف — ويعرف الدعم — أي نسخة تعمل الآن.

### 19. طبقة التشخيص على الصورة (v108)

- من **الإعدادات ← تفضيلات العارض ← «طبقة تشخيص على الصورة»** يمكنك إظهار سطور تشخيصية فوق
  الصورة: رقم الإصدار، السلسلة والشريحة، الأبعاد، طول المخزن مقابل المطلوب، مدى البكسل، عمق
  البتّ، صيغة النقل، النافذة المستخدمة فعليًا، والتباين الناتج ونسبة القيمة المهيمنة. **لقطة
  شاشة واحدة تكفي** لمعرفة سبب أي صورة فارغة. الافتراضي: مطفأة.
- **لوحة السبب** تحمل الأرقام نفسها، فلا يظهر إطار أسود بدون دليل.
- **تكبير نوافذ MPR**: اضغط عنوان النافذة (أو انقر مرتين عليها) لتكبيرها على عرض الشبكة كاملًا.
- **تنبيه «غير معتمد للتشخيص»** أسفل العارض، مع زر «إخفاء» يُتذكَّر على الجهاز.

### 20. هل الخلل في البيانات أم في الرسم؟ (v109)

- **قراءة مرتدة من الصورة (readback)**: عند تشغيل طبقة التشخيص، يقرأ العارض الصورة بعد رسمها
  ويكتب `paint=ok/255` أو `paint=uniform`. كلمة واحدة تفصل بين «الإطار لا يحتوي ما يُعرض»
  و«البكسلات لم تصل إلى الشاشة».
- **زر «فحص السلسلة»**: يرسم عيّنة من شرائح السلسلة المختارة خارج الشاشة ويخبرك: كم إطارًا بلا
  بيانات بكسل، وكم إطارًا من المفحوص يُرسم فارغًا — بضغطة واحدة ودون لقطات.
- **شاردة صحة البكسل في قائمة العمل**: أي دراسة تحوي إطارات بلا بيانات بكسل تُوسم بـ
  «⚠ N بلا بكسل» في عمود الشرائح. تُحسب عند الاستيراد، وتُحسب تلقائيًا للدراسات التي
  استُوردت بإصدارات أقدم.

### 21. انتهاء حلقة التحديث المتكرّر (v110)

كان المُطلِق (`start.html`) يحتفظ بجدول تحقّق (ما هو حجم كل ملف وبصمته) وكان يبنى قديمًا
باستبدال رقم الإصدار كنصّ — فتحوّلت كل مفاتيح الإصدارات السابقة إلى مفتاح الإصدار الحالي.
في JavaScript المفتاح المكرَّر **آخره هو الذي يُستعمل**، فكان المُطلِق يتحقّق من ملفات الإصدار
الجديد ببصمات إصدار قديم جدًا: تفشل كل المرايا، فيرجع التطبيق إلى إصدار أقدم، ويرى الإصدار
الأقدم أن هناك تحديثًا فيعيد التحميل … وهكذا بلا توقف.

- **يُبنى الجدول الآن من الملفات نفسها**: المُطلِق لا يحمل إلا بصمات الإصدار الحالي، محسوبة من
  ملف `integrity.v110.json`، وكل إصدار آخر يُتحقَّق منه عبر ملف البصمات الخاص به من نفس المصدر.
- **قائمة الإصدارات الاحتياطية** تُولَّد مرتبة تنازليًا بلا تكرار (v110 … v35)، والأحدث يُجرَّب
  أولًا دائمًا.
- **سقف لإعادة التحميل**: إن توفّر تحديث، يعيد التطبيق التحميل **مرتين كحدّ أعلى** لكل إصدار،
  ثم يكتفي بعرض رابط «افتح المُطلِق» بدل الاستمرار في الدوران. وعند وصول الجهاز إلى أحدث
  إصدار تُمحى العدّادات.
- **مراقب الإصدارات كان ينادي نفسه** بدل أن يفحص التحديث (ما كان يعطّله تمامًا) — أُصلح ووُصل
  بدورة التطبيق، فيفحص كل ٥ دقائق وعند رجوعك إلى التبويب.

> إن رأيت سطر «تحديث متاح … جارٍ تحميله» أكثر من مرة، فالحل من خطوة واحدة: افتح
> `start.html`، فهو يعيد التحقق من كل ملف مقابل بصمته ويشغّل أحدث إصدار.

### 22. المُطلِق ملف تحكّم — لا يُقدَّم من المخبأ (v111)

حين يفشل المُطلِق في التحقق من أي إصدار، يعرض شاشة الخطأ ثم **يفتح نسخة الملف الواحد تلقائيًا**
(خلال 1.2 ثانية، ويخبرك بذلك على الشاشة). لذلك إن رأيت تلك الشاشة لحظةً ثم فتح التطبيق، فهذا
هو المسار الاحتياطي يعمل كما صُمّم.

- **المُطلِق لم يكن محميًا من المخبأ**: كان `start.html` يُقدَّم من مخزن عامل الخدمة، فتصل نسخة
  قديمة منه تحمل بصمات إصدار سابق — فيرفض كل إصدار جديد ويعيد الجهاز إلى إصدار قديم. الآن
  يُجلب دائمًا من الشبكة (`no-store`)، ويُتحقَّق من طوله مقابل جدول بايتات الإصدار، ثم يُعاد
  طلبه برابط مكسور للمخبأة إن كان قديمًا أو محرَّفًا.
- **عند العمل بدون إنترنت** يُفضَّل فتح نسخة الملف الواحد (مكتفية بذاتها) على مُطلِق لم يعد
  قادرًا على التحقق من شيء.
- لاحظنا في شبكتك أن بعض الردود تُحرَّق بمحتوى مُنشَأ (`cdn.connecttag.app`). التحقق بالبصمة
  يرفضها — وهذا دليل على أن الحماية تعمل، لا على وجود عطل.

### 23. حين يرفض التطبيق استيراد الملفات (v112)

كانت الرسالة القديمة تقول دائمًا: «الملفات تالفة أو بصيغة تعذّر فكّها… راجع سجل الطرفية» —
حتى حين لا يكون هناك أي تلف. **الرسالة الآن تسمّي السبب الفعلي بالعدد:**

| السبب | ما تراه |
|---|---|
| الدراسة موجودة مسبقًا | «3 دراسات مكررة موجودة مسبقًا على هذا الجهاز — افتحها من قائمة العمل» |
| ملفات ليست DICOM | «12 ملفًا غير مقروءة كملفات DICOM» |
| ملفات مضغوطة تعذّر فكّها | «4 ملفات مضغوطة تعذّر فكّها (1.2.840.10008.1.2.4.50) — تحتاج مفكّها مرة واحدة مع اتصال بالإنترنت، ثم تُحفظ للعمل دون إنترنت» |
| بلا عنصر بكسل / أرشيف فارغ | «5 ملفات بلا عنصر بيانات بكسل» — «2 أرشيف بلا أي ملف DICOM» |
| بيانات بكسل فارغة أو ناقصة | «7 ملفات بيانات بكسلها فارغة أو ناقصة أو متطابقة» |

> إعادة استيراد الدراسة نفسها **لا يضيف شيئًا جديدًا** — افتراضيًا يُتخطّى التكرار، والرسالة
> تقول لك ذلك صراحة بدل اتهام ملفاتك بالتلف.

### 24. تقرير استيراد قابل للنسخ (v113)

حين يُرفض استيراد ملفاتك، لا داعي للقطات شاشة: يظهر زر **«نسخ تقرير آخر استيراد»** أسفل لوحة
الاستيراد. اضغطه فيُنسخ (ويُعرض) تقرير نصّي يصف ما رآه الجهاز ملفًا بملفًا:

```
Import report — 06/10/2026، 00:41 — build v113
file IMG001 bytes=527384 magic=4449434d single
  IMG001 ok 512x512 ts=1.2.840.10008.1.2.1 len=524288
file study.zip bytes=44123904 magic=504b0304 zip entries=219
  IMG002 parse-error: no DICM magic
duplicate of a study already on this device: ALI ABDULLAH|20261004|MR|24
```

- `magic` يكشف نوع الملف الحقيقي (`4449434d` = DICOM، `504b0304` = ZIP، `89504e47` = صورة).
- كل ملف يُذكر سببه: `ok`، أو `parse-error`، أو `decode-error` مع صيغة النقل، أو `no-pixel-element`،
  أو `pixel-problem` مع الطول مقابل المطلوب.
- **الدراسة المكررة تُفتح تلقائيًا**: إن كان الرفض كله لأن الدراسة موجودة مسبقًا، يفتحها التطبيق
  من قائمة العمل بدل أن يقول لك إن شيئًا أُضيف.

### 25. نوافذ MPR: منزلق شريحة ونافذة (W/L) لكل نافذة (v114)

- **منزلق شريحة مستقل** أسفل كل نافذة (محوري / إكليلي / سهمي): يحرّك مستوى تلك النافذة وحده،
  ويبقى متزامنًا مع مؤشر التقاطع (crosshair) حين تضغط أو تسحب على نافذة أخرى.
- **نافذة (W/L) مستقلة لكل نافذة** بقائمة منسدلة: `تلقائي` (تتبع النافذة المشتركة)، `نسيج رخو`،
  `منصف`، `عظم`، `رئة`، `دماغ`. اختيارك يُحفظ على الجهاز، فتبقى العظم على السهمي والنسيج الرخو
  على المحوري في كل مرة تفتح فيها الدراسة.
- **عنوان النافذة يذكر النافذة المطبّقة** مثل `عظم 1.500` (الاسم ثم عرض النافذة بوحدات HU)، كما في
  العارض المرجعي.
- وأُضيفت نافذتا **«نسيج رخو»** و**«دماغ»** إلى قائمة النوافذ المشتركة أيضًا.

### 26. الشاشة السوداء: التشخيص التلقائي وإرجاع الوحدات إلى إصدارها (v115)

**أهم إصلاح في هذا الإصدار:** كان التطبيق يستورد وحداته (محلّل DICOM، MPR، التقرير، المفكّكات …)
من الإصدار **v59** — أي أن كل إصدار من v59 إلى v114 كان يعمل بمحلّل قديم، وملف `mpr.v59.js`
**لم يُنشر أصلًا**، فكانت وحدة MPR تفشل في التحميل (404) بصمت. المحلّل القديم لا ينتج حقل
`pixelInfo`، فلا تظهر لوحة السبب ولا يعمل إنقاذ النافذة: **صورة سوداء بلا أي تفسير**.

- **كل وحدة تُستورد من الإصدار الحالي**: `roll.py` يعيد كتابة هذه المسمّيات عند كل إصدار،
  و`--check` يرفض أي إصدار يستورد وحدة من إصدار آخر أو وحدة غير موجودة.
- **تشريح تلقائي عند كل رسم**: بعد كل رسم يقيس العارض الكانفاس كما تراه الشاشة فعليًا — أبعاده
  على الشاشة، نمطه المحسوب (`display/visibility/opacity/position`)، العنصر الذي يغطّيه فعليًا
  (`elementFromPoint`)، وقراءة البكسلات المرتدة بعد الرسم. فإن لم تصل الصورة إلى الشاشة، يكتب
  السبب في سطر الحالة ويعرض **تقريرًا جاهزًا للنسخ** بضغطة واحدة — دون أي إعداد ودون لقطة شاشة.
- **إصلاح ذاتي للتخطيط**: إن كان الكانفاس بلا أبعاد (لأن التخطيط استقرّ متأخرًا) أو مخفيًا أو
  مغطّى، يضعه العارض في مجرى الصفحة ويعيد القياس، ويكتب `أُصلح التخطيط` إن نجح.
- **زر «إعادة الرسم»** بجانب منزلق الشريحة: يصفّر القياس المحفوظ ويعيد ضبط الإطار والرسم بضغطة.

أسباب الشاشة السوداء أصبحت مميّزة ومذكورة بالاسم: `no-size` (لا أبعاد)، `hidden` (مخفي)،
`covered:<id>` (مغطّى بعنصر آخر)، `no-frame` (لا إطار)، `uniform` (كل البكسلات بقيمة واحدة).
